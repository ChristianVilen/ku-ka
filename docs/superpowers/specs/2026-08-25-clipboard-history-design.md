# Clipboard History — Design

**Date:** 2026-08-25
**Status:** Proposed (pending review)
**Branch:** `add-clipboard-mgmt`

## Summary

Add a clipboard history to Ku-Ka, in the spirit of Raycast's: the app records what
the user copies, and `Shift+Cmd+C` opens a glass panel listing the history. Arrow
keys move the selection, typing filters the list, Enter pastes the item into the
app the user was working in. For formatted text, Enter first asks "with or without
formatting", with "without" as the pre-selected first option.

History lives in memory only and is capped. Nothing is written to disk.

This feature also raises the app's minimum system version to macOS 26, so the
panel can use the real Liquid Glass material (`NSGlassEffectView`).

## Goals

- Record clipboard changes: plain text, rich text flavors (RTF, HTML), and images.
- `Shift+Cmd+C` opens the panel on the screen where the cursor is.
- Type to filter, Up/Down to move, Enter to paste, Esc to close.
- Formatted text gets a two-row chooser on Enter: "Paste without formatting"
  (first, pre-selected) and "Paste with formatting". Plain text and images paste
  at once, with no chooser.
- Paste lands in the app that had focus before the panel opened, without a
  visible app switch.
- A "Clipboard History" checkbox in the status menu, default on. Off means: the
  poll stops, the hotkey passes through to other apps, and the history is cleared.
- Ku-Ka's own screenshots appear in the history like any copied image. Deleting a
  screenshot from the thumbnail or editor also removes its history item.
- Items marked as concealed, transient, or auto-generated are never recorded.

## Non-goals

- No storage on disk. History is empty after a restart. (Chosen over persistence.)
- No encryption, since nothing is stored.
- No per-item delete and no "clear history" menu item. Toggling the feature off
  is the reset.
- No pinned items, snippets, OCR, link/color/file detection, preview pane, or
  type filter. These are Raycast features we may add later.
- No app exclusion list.
- No configurable hotkey, poll rate, or caps.

## Mechanism

macOS has no notification for clipboard changes, so the controller polls
`NSPasteboard.general.changeCount` every 0.5 s on a main-queue timer. Maccy and
Raycast work the same way.

When the count changes:

1. If the pasteboard carries `org.nspasteboard.ConcealedType`,
   `org.nspasteboard.TransientType`, or `org.nspasteboard.AutoGeneratedType`,
   skip the item. Password managers set these.
2. Otherwise read an image (PNG, else TIFF re-encoded as PNG), else text:
   the plain string plus RTF and HTML flavors when present.
3. Items are keyed by a SHA-256 hash of the payload (plain-text bytes, or PNG
   bytes). Copying content already in the history moves that item to the top
   instead of adding a duplicate.

Pasting: write the chosen item back to the pasteboard (plain only, or plain plus
rich flavors), close the panel, and synthesize `Cmd+V` key events with `CGEvent`.
The event flags are set to exactly `.maskCommand`, so modifier keys the user is
still holding do not leak into the paste. Accessibility permission covers this;
the app already requires it. Our own pasteboard write bumps `changeCount` too,
so the controller immediately adopts that count as the new baseline — self-write
suppression — instead of waiting for the next poll to read our own write back.
The pasted item still needs to move to the top of the history, though, and with
its full flavors intact even when the paste itself was plain-only: a real
pasteboard write without formatting only puts the plain string on the system
pasteboard, so letting a later poll re-read it would silently downgrade the
stored item and the chooser would never offer it again. The controller avoids
that by re-adding the original in-memory item straight into the history right
after the write; the existing dedupe-to-top rule moves it to the top without
touching what it's made of.

## Panel UI

- `ClipboardPanel` builds on `FloatingPanel` (borderless, non-activating) and
  overrides `canBecomeKey` to true. A non-activating key panel receives
  keystrokes while the target app stays active, so no focus juggling is needed.
- Background is an `NSGlassEffectView`. Content: a search field on top, an
  `NSTableView` list under it.
- Rows show a type icon and one line of preview text; image rows show a small
  thumbnail and a label like "Image 938×773". Newest first. The first row is
  pre-selected when the panel opens, so "open, Enter" pastes the latest item.
- The filter matches what the row shows: text items match their content,
  image items match their label. Case-insensitive substring.
- Placement: horizontally centered on the screen where the cursor is, in the
  top third (Spotlight placement).
- Keys: typing edits the filter; Up/Down moves the selection; Enter pastes or
  opens the chooser; Esc closes. The panel also closes when it loses key status
  (click somewhere else).
- The chooser replaces the list with two rows; Up/Down and Enter work as in the
  list, Esc goes back to the list.
- Empty history shows a single "Nothing copied yet" line.

## Limits

- At most 100 items. The oldest item is evicted first.
- At most ~100 MB of image bytes in total; evict oldest until under budget.
- A single item above 50 MB is not stored at all.
- Images are held as compressed PNG data. Full bitmaps are decoded only to
  render the small row thumbnail, never kept.

## Raising the minimum to macOS 26

`NSGlassEffectView` needs macOS 26. Decision: raise the whole app instead of
keeping a fallback path. Users on macOS 14/15 keep the last released version.

## Architecture

Follows the house pattern: pure model, seam protocols, one `@MainActor`
controller, AppKit views kept dumb.

- `ClipboardItem` (new file) — value type. Kind is `.text(plain, rtf: Data?,
  html: Data?)` or `.image(png: Data, pixelSize)`, plus content hash, copy date,
  and byte cost. `hasRichFlavors` decides whether Enter shows the chooser.
- `ClipboardHistory` (new file) — pure model, no AppKit: ordered list,
  dedupe-to-top, both caps with eviction, filter, remove-by-hash, clear.
- `PasteboardReading` / `PasteboardWriting` + `SystemPasteboard` (new file) —
  the seam over `NSPasteboard.general`: change count, read the current item
  (nil for marked, oversized, or unsupported content), write an item with or
  without formatting.
- `KeystrokeSending` + `CGEventKeystrokeSender` (same file) — sends the
  synthetic `Cmd+V`.
- `ClipboardHistoryController` (new file) — `@MainActor`. Owns the timer, the
  history, and the panel. Handles the hotkey action, the chooser decision, the
  paste hand-off, enable/disable (stop + clear), and removal when a screenshot
  is deleted.
- `ClipboardPanel` (new file) — the glass panel, search field, list, chooser.
  View only; actions go back to the controller through closures.
- `HotkeyManager` — new case `HotkeyAction.showClipboardHistory` for
  `Shift+Cmd+C` (key code 0x08), gated by a `clipboardHistoryEnabled` flag the
  same way `tilingEnabled` gates the tiling combos.
- `Settings` — `clipboardHistoryEnabled`, default true.
- `StatusMenu` — "Clipboard History" checkbox next to "Window Tiling", plus a
  line in the Features section.
- `AppDelegate` — owns the controller and wires hotkey, toggle, and the
  `ImageStore` deletion hook.
- `ImageStore` — keeps a session-scoped map from saved file URL to the set of
  content hashes of the PNGs it copied for that file (annotation adds a
  second), and reports each hash on `delete(at:)` through a closure so the
  controller can drop the matching item.

## Testing

TDD (red-green) on the logic, per the repo convention. AppKit views and the
real pasteboard adapter stay untested like the other features' views.

- `ClipboardHistoryTests` — add puts newest first; duplicates move to the top
  without growing the list; the 101st item evicts the oldest; the image byte
  budget evicts; oversized items are refused; filter and remove-by-hash work;
  clear empties.
- `ClipboardHistoryControllerTests` — against a fake pasteboard and a fake
  keystroke sender: a change-count bump reads one item; no bump reads nothing;
  marked items are skipped; disable stops the poll and clears; enable resumes;
  paste writes the right flavors and sends `Cmd+V`; the chooser appears only
  for items with rich flavors; a reported screenshot hash removes its item.
- `HotkeyManagerTests` — `Shift+Cmd+C` is swallowed and routed while enabled,
  passes through while disabled; the screenshot and tiling combos behave as
  before in both states.

## Accepted trade-offs and risks

- `Shift+Cmd+C` is swallowed globally while the feature is on. Chrome and Arc
  lose Inspect Element, Xcode loses Activate Console, VS Code loses Open
  External Terminal, Finder loses the Computer window. The menu checkbox gives
  the key back.
- The synthetic `Cmd+V` does not reach apps during secure input (password
  fields) and apps that reject synthetic events. The item is still on the
  clipboard, so a manual `Cmd+V` works.
- Two copies inside one 0.5 s tick: only the second is recorded. Every polling
  clipboard manager shares this.
- The exact glass composition (scrim, corner radius, contrast against busy
  wallpapers) will need tuning by eye during implementation.
