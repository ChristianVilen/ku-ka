# KuKa domain glossary

- **Calendar occurrence.** One calendar event instance, identified by its calendar, item, and original recurrence date. `EventKitCalendarSource` reads immutable snapshots and keeps safe provider aliases within its lifetime. `CalendarReminderController` owns eligibility, reminder tokens, receipts, and one recording association. `CalendarReminderDriver` owns refresh signals. `CalendarReminderNotifications` builds native requests while `SystemNotifier` remains the only delegate. The integration is off by default, and the Settings window's Calendar reminders switch turns it on through `CalendarReminderController.setEnabled(_:)`. The exact interface and limits are in `docs/calendar-recording-reminders.md`.
- **Meeting display title.** Optional bounded `meeting.json` metadata saved before capture. It preserves the dated folder name, equality, and stage rules. `MeetingTitle` normalizes the text and escapes document headings. The recorder's session fixes the title at Start. The existing menu status shows it with a bounded suffix and a full tooltip and accessibility label.

- **Capture** — producing a screenshot image from a screen region, window, or full screen. Owned by `CaptureManager`; the produced image goes straight to the image store.
- **Image store** — everything that happens to a produced image: disk writes under the Screenshots directory, clipboard, file naming, combining two captures into one, annotation overwrites, deletion, and returning freed memory to the OS. Owned by `ImageStore`.
- **Selection session** — one round of "user picks what to capture": overlays appear on every screen, the user drags a rect, picks a window (Space toggles window mode), or cancels (Esc). Ends with a single `SelectionResult` carrying the screen the capture belongs on. Owned by `SelectionSession`.
- **Capture flow** — the pipeline from hotkey to thumbnail: run a selection session (or pick the screen under the mouse for fullscreen), wait for the overlay to settle, capture, flash on fullscreen, hand the result to the thumbnail stack. Owned by `CaptureFlow`.
- **Thumbnail stack** — the pile of floating capture previews in the screen corner; entries can be edited, combined, deleted, or left to expire. Owned by `ThumbnailStackManager`.
- **Editor** — the window opened from a thumbnail to change a capture before it is saved over: freehand strokes on a `DrawingView`, a crop box on a `CropOverlayView`, and Done/Delete routed to the image store. Owned by `EditorWindow`.
- **Crop box** — the adjustable rectangle that marks the part of a capture to keep: drawn, moved, resized from edges and corners, flipped when a handle is dragged past the opposite side, removed by a click outside it. Pure geometry in view points, owned by `CropBox`; the mapping to image pixels on save belongs to `DrawingView.pixelRect(for:in:imagePixelSize:)`, used by both the save and the overlay's size label.
- **Tiling** — moving the focused window to half/maximized/centered positions across screens via hotkeys. Owned by `WindowTilingController`.
- **Keep awake** — a timed session preventing system/display sleep. Owned by `WakeManager` / `KeepAwakeController`.
- **Clipboard history** — what the user has copied (text and images), recorded as it happens and shown in a panel opened with Shift+Command+C. Owned by `ClipboardHistoryController`.
- **Screen layout** — the displays as plain geometry (`ScreenGeometry`: frame + visible frame), vended by the `Screens` seam so tests can fabricate multi-display layouts. Ambient `NSScreen` reads live only in system adapters. Shared screen math belongs to `ScreenCoordinates`: coordinate flips between NS (bottom-left) and CG/AX (top-left), and the "which screen owns this rect" rule used by tiling and selection. The matching "which screen is the pointer on" rule sits on `ScreenGeometry` itself (`ScreenGeometry.under(_:in:)`, in `Screens.swift`), because it is about a point and a layout rather than about coordinate systems; full-screen capture, the selection session, and the clipboard panel all ask it.
- **Registered shortcuts** — seven fixed combinations requested by `HotkeyManager`, which owns feature toggles, retry, and wake handling. `CarbonHotkeyRegistrar` alone owns actual registrations, pending releases, and event IDs. It applies the desired set and returns issues. Tests replace the five OS calls in `CarbonHotkeyAPI` while exercising the real registrar.
- **Hotkey health** — the `HotkeyHealth` value built by `AppDelegate.updateStatus()` from current permission and registration state. `StatusMenu` renders affected shortcuts, release failures, and setup guidance, skipping unchanged values. There is no separate monitor or cached copy of the owners' state.
- **Screenshot shortcut setup.** Guidance in the shared Ku-Ka window's Permissions page, revealed once when macOS owns Ku-Ka's screenshot combinations. `Settings.didShowScreenshotShortcutSetup` records presentation only after the page is visible. Permissions and shortcut setup use the same page.
- **Settings** — the user's preferences (thumbnail duration, window tiling on/off, clipboard history on/off, display awake, summary tool, meetings folder, known-words file, optional meeting-context file, meeting locale, the meeting controls' position and transcript height, launch at login), with every key and default defined once. Owned by `Settings`.
- **Ku-Ka window.** One retained native window owned by `SettingsWindowController`, with Settings, Features & instructions, Permissions, and Help & feedback pages. Preferences save immediately and send typed runtime effects through `AppDelegate`. Opening only reads values. This window, word review, and typed notes share `OrdinaryWindowActivation`. The app returns to accessory mode after the last ordinary window closes. The application menu provides Command-comma, Command-Q, Command-W, and the Edit commands.
- **Launch hosts.** `main.swift` selects `AppLaunchMode` once. XCTest has no app delegate and never constructs production services. `--uitesting` uses `SettingsPreviewAppDelegate`, isolated `KuKa.TestHost` defaults, inert login management, and the static menu. XCTest takes priority over the preview argument.
- **Summary tool.** Automatic tries `agy`, then `claude`. An explicit tool never changes provider. `MeetingNotesController` reads `Settings.summaryTool` once when a queued job starts and passes the value through the processor. A running job keeps its choice.
- **Status menu** — the menu-bar menu and status-item icon: operational commands, the Settings entry, and the keep-awake and recording badges. Owned by `StatusMenu`.
- **Meeting.** One recording of a call that the user starts from the menu and stops from the menu or the meeting controls, and the notes Ku-Ka makes from it. The recording in progress belongs to `MeetingRecorder`. Durable processing state lives in the meeting folder. Optional Teams observations accompany the queued job in memory until processing finishes.
- **Meetings folder.** The root for new meetings, selected in **Settings…** beside **Meetings folder**. `Settings.meetingsFolder` reads and writes the `meetingsFolder` defaults key, and the default is `~/Meetings`. Selection applies immediately; Cancel changes nothing. Existing meetings stay where they are, and active and queued work keeps its original folder. The default known-words path follows the selected root; an explicit path stays fixed.
- **Meeting folder.** One meeting on disk, `<meetings folder>/<yyyy-MM-dd_HH-mm>/`, with `audio/me.caf` and `audio/them.caf` until the transcript exists, then `transcript.md`, `summary.md`, and `error.md` while a step is failed. Hidden next to them is `.transcript-as-heard.md`, the transcript before known words, and a meeting with questions about words has `review.json`, and `review-skipped.json` after a Skip. These files and optional typed notes in `notes.md` never change the stage. A meeting with no speech and no typed notes keeps its audio. The folder is the only state that outlives a click. Recovery and Retry read it, and nothing else records progress. Owned by `MeetingFolder`.
- **Folder lock.** A `flock` on the hidden `.lock` file in a meeting folder. It permits one recorder or processor across Ku-Ka processes. Typed notes use a separate `.notes.lock` because writing notes must remain possible while the recorder or processor holds the general lock. The system releases both locks when their owners or processes end.
- **Typed meeting notes.** User-authored plain text or Markdown in `notes.md`. The file is summary input and never changes `MeetingStage`. `MeetingTypedNotesSession` owns one folder-bound draft, synchronous atomic saves, a separate lock, and save and summary status. `MeetingNotesController` retains one session per open or unsaved editor. Saved windows release their session when closed. The resizable native window uses `NSTextView` and its own undo manager. Recording controls and the recent-notes menu open it.
- **Summary-only update.** The typed editor's **Update summary** queues `MeetingProcessor.updateSummary`. It reads saved `transcript.md` and one saved notes snapshot, then writes only `summary.md`. It preserves transcript corrections and word-review files. Updates are explicit. Edits made during generation remain marked as needing another update. This differs from the word-review flow's **Update Notes**, which rebuilds the transcript from the heard copy.
- **Track.** One audio source of a meeting. The microphone and the sound the Mac plays each have their own file. `MeetingTrack` lists those sources, and `MeetingTrack.speaker` maps them to the fallback labels "Me" and "Them". After Stop, SpeakerKit can separate microphone voices, and `Transcript.merge` gives them "Room 1", "Room 2", and later room numbers. These labels identify voices, not people. Supported Teams names can replace "Them" on system lines. Each line keeps its original track.
- **Teams speaker evidence.** Optional, experimental observations from the Teams desktop app's Accessibility tree. `teamsSpeakerNamesEnabled` defaults false and is read once per recording. The recorder owns an in-memory history, pauses observation with audio, and hands immutable evidence through the processing queue at Stop. `TeamsSpeakerEvidence` names only sufficiently covered remote segments before transcript joining. A label such as "Aino (Teams)" is UI evidence, not a voice identity or proof of action ownership. Unknown or ambiguous observations keep "Them". A scan that finds no name records why, as a `TeamsScanReason`. The log and one line in `transcript.md` report these reasons as codes and counts, never with a name. Recovery without that memory uses "Them"; saved names survive Update Notes through the heard transcript. The selectors have not been verified in a real call.
- **Stage.** What a stopped meeting still needs. A stage is pending transcription, pending summary, failed at one of those steps, or done. `MeetingStage` derives it from which files exist in the meeting folder and never stores it. `MeetingProcessor` moves a folder from any stage to done.
- **Echo.** A "Them" line that the microphone also picked up from the speakers. `Transcript.isEcho` finds it by time overlap and shared words, and the merge drops it from "Me".
- **Pause.** A span of a meeting that Ku-Ka does not record. The capture stream, the files, and the folder lock stay, and both tracks drop the same span, cut at the host time of the click. Each resume leaves 3 s of silence in both files, so the final transcript never joins speech across a pause. `RecordingClock` holds the pauses, and `MeetingRecorder` is the only code that changes it. Only the clock reads their stored host times. Other code asks it for derived values, such as the pause list for the live transcript or the file intervals for Teams speaker evidence.
- **Recorded time.** The length of a meeting without its pauses. The meeting controls, the menu, and the live transcript show it, and it stands still while paused. A time in `transcript.md` is a file position instead, which is the recorded time plus 3 s for each earlier resume. `RecordingClock` maps a host time to both, and a host interval to the file intervals of its kept parts.
- **Live transcript.** The draft text of a meeting while it records, from Apple's `SpeechTranscriber` on the audio Ku-Ka has just written. It stays in memory, never goes to disk, and goes away at Stop, when the final pass writes `transcript.md`. Only a language whose Apple speech model is already installed gets one, and Ku-Ka never downloads a model for it. `AppleLiveTranscriber` makes it, and `LiveTranscript` holds it.
- **Meeting controls.** The floating panel of a meeting. A pill shows the state, the recorded time, Pause or Resume, and Stop, and a drawer that opens from the pill shows the live transcript. The drawer starts closed in every meeting. After Stop or an interruption, the pill shows a notice. `MeetingRecorder` owns everything the panel shows, as a `MeetingControls` value, and `MeetingControlsPanel` draws it, with the live transcript in a `MeetingTranscriptDrawer`.
- **Meeting context.** Optional UTF-8 Markdown background about project terms, vendors, and people, selected by `Settings.meetingContextFile`. `MeetingContextFile` reads it for each summary, including retry and both update actions. The cap is 16 KiB. Missing or blank content adds no block. Invalid, unreadable, oversized, or nonregular files and files with NUL bytes are logged and skipped. The complete accepted text goes to the CLI provider. It is data, never instructions. Transcript and typed-note evidence take priority, and background cannot supply unsupported decisions or owners. Context never changes the transcript or CLI isolation.
- **Known words.** The user's Markdown list of names and terms that speech recognition gets wrong: each line has heard forms and one right form. A heard form with ✓ is confirmed, and Ku-Ka replaces it in `transcript.md`; a form without ✓ is provisional and only helps the summary. Ku-Ka reads the list at each use and only inserts lines into it. `KnownWordsList` reads it, and `KnownWordsFile` owns the file. Only matching forms go to the CLI, unlike meeting context, which goes in full.
- **Word review.** Up to 5 questions per meeting about words that the summary CLI thinks speech recognition got wrong, asked in the review window after the notes are ready (Check Words). An answer is a right word, "correct as heard", or Skip. A right word and "correct as heard" become a line in the known-words list and are kept nowhere else; a Skip is kept only in the meeting folder. A question is open while it is not skipped and the list does not know its word, so an answer in one meeting closes the same question in the others, and a list line removed later opens it again. **Update Notes** is offered when the list learned a word of the meeting, also from an answer in another meeting. It makes the notes again with the list, and `transcript.md` again from the heard copy, so a hand edit to it is lost. `WordReviewController` owns the state and the writes, and `WordReviewWindowController` draws it.
- **Ordinary words.** A heard form whose words are all in the dictionary of the meeting language, such as "my key". A right word for it is saved without ✓, so it is not replaced in every transcript. Names (person, company, product) are never ordinary words.
